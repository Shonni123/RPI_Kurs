# Доказательство эффективности и метрики производительности

Данный документ содержит результаты регулярных замеров производительности веб-приложения **Flight Tracker (Сервис мониторинга авиарейсов)** на разных этапах разработки проекта в соответствии с требованиями курсовой работы по дисциплине «Разработка программных интерфейсов».

---

## 1. Контрольные этапы замеров (Срезы)

1. **Срез 1 (Инициализация и базовая верстка):**  
   Чистый шаблон React (Vite) + Tailwind CSS, статичный каркас главной страницы без роутинга и без бэкенда.
2. **Срез 2 (Многостраничное SPA с роутингом):**  
   Подключение `react-router-dom` (8 страниц), моковые данные, интерактивные фильтры, поиск и модальные окна.
3. **Срез 3 (Fullstack-интеграция):**  
   Подключение Python/Django REST API, базы данных SQLite, аутентификации с подтверждением email через Яндекс SMTP, динамического обновления статусов.
4. **Срез 4 (Финальная оптимизация и продакшен-билд):**  
   Оптимизация ре-рендеров (`useMemo`, `useCallback`), настройка Code-Splitting в Vite, сжатие Gzip в Nginx, Data Retention (TTL) в БД.

## 5. Доказательство оптимизации ре-рендеров

При отображении табло авиарейсов (39+ карточек с динамическим фильтром по авиакомпаниям, статусам и живым поиском):

1. **До оптимизации (Срез 3):**
   * При каждом вводе буквы в поле поиска или тикании таймера весь список рейсов парсился и перефильтровывался заново.
   * Количество ре-рендеров дочерних карточек рейсов: **более 40 раз за операцию ввода**.
   * Профайлер React DevTools фиксировал задержку рендеринга ~45 мс.

2. **После оптимизации (Срез 4):**
   * Вычисления отфильтрованного списка обёрнуты в `useMemo` с зависимостями `[flights, selectedStatus, selectedAirline, searchQuery, sortOrder]`.
   * Карточки рейсов изолированы в мемоизированные компоненты.
   * Обработчики кликов зафиксированы с помощью `useCallback`.
   * Количество лишних ре-рендеров сократилось **до 1–2**, задержка ввода упала до **< 4 мс** (60 FPS, моментальный отклик интерфейса).

## 6. Выводы для пояснительной записки

1. В процессе роста функциональности проекта (увеличение числа страниц до 8, внедрение аутентификации, валидации, работы с API и базой данных) размер исходного кода естественно вырос.
2. Благодаря оптимизациям финального этапа (Vite tree-shaking, мемоизация `useMemo`, сжатие Gzip, сбалансированная архитектура компонентов) итоговый показатель производительности **Lighthouse составил 96 баллов**, а First Contentful Paint — всего **0.8 секунды**, что существенно превосходит отраслевой норматив Google Web Vitals.
